# Archive

Historical specs and implementation plans, one file per piece of work, named by the date it was
written. They record what was intended at that moment — **not** how the system works now.

Nothing here is maintained. A plan from April describes an April codebase; where it disagrees with
the source, the source wins. For current behaviour read [the docs index](../README.md); for why a
structural decision was made, read the [ADRs](../architecture/adr/).

| Directory | Contents |
|---|---|
| [`specs/`](specs/) | Designs written before implementation — problem, options, chosen shape |
| [`plans/`](plans/) | Step-by-step execution plans produced from those designs |

These files lived under `docs/superpowers/` until 2026-08-16, after the tool that generated them.
Internal links inside archived documents still use that old path; they are left as written, because
rewriting the contents of an archive to look current is exactly the confusion this split removes.
