# Plan-Mode (B1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in `plan_review` pipeline stage that auto-generates the implementing agent's execution plan, auto-self-reviews it, and gates on human approval before the implementation stage edits any files.

**Architecture:** `plan_review` is a new free-form stage string inserted between `backlog` and `implementation` in `StageOrder`. It is an agent-driven stage whose builder prompt does two phases in ONE spawn (draft plan from the concept, then self-critique and rewrite into a vetted plan — only the vetted plan is output). On completion the stage gates to `awaiting_user` (WaitUserTransition); `approve_plan` freezes the plan and advances to `implementation`, `reject` re-runs the stage with feedback up to a cap. The whole feature is gated by a per-task `plan_mode` bool (default false) with a per-project/global default via `pipeline_config`; when off, the state machine is byte-for-byte today's flow.

**Tech Stack:** Go (ent ORM, chi, pipeline state machine), Vue 3 + TS (Vitest). No stage enum/migration — stage is `field.String`. Only DB change: `task.plan_mode` bool.
