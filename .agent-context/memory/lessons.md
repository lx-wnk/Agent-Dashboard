- **[frontend/lint]** `pnpm lint` runs ESLint repo-wide and is **chronically red on toml/yaml config files** (antfu config's `toml/*` + `yaml/*` plugins). - **[frontend/vue]** The ESLint config enforces **camelCase custom event names** (`vue/custom-event-name-casing`). Kebab-case emits (`'open-sessions'`) fail lint; declare/emit `openSessions` instead. Template listeners may stay kebab (`@open-sessions`) — Vue normalizes them. The rule flags the `emit()`/`$emit()` call + `defineEmits` key, not the listener attribute. `update:xxx` v-model events are exempt when already camelCase. `conf:high` (2026-05-30)
- **[backend/auth]** Default auth mode is `DASHBOARD_AUTH=none` (`config.go` default) → `BypassAuth=true` → `RequireAuth` middleware is **skipped**, so **no JWT payload is ever placed in the request context**. Handlers must NOT re-gate on `auth.PayloadFromContext()` and 403 when absent — that breaks every route in the default (bypass) config. Auth is enforced at the middleware layer only; handlers trust it (`payload, _ :=`, never `if !ok { 403 }`). The refine handlers (`api/refine/handler.go`) had this bug → all 3 routes 403'd in bypass mode. Fixed across the board (2026-05-30): refine + wphandler dropped the dead guards (payload discarded); `search`/`remotes`/`history` substitute `auth.BypassPayload()` (SSOT helper in `internal/auth/jwt.go`, `Sub="local"`/`IsAdmin=true`, matching `/api/me` via `auth.BypassUserID`) on `!ok` instead of 403 — needed because they key per-user data on `payload.Sub`. `presets` was already correct (`if ok { userID=&Sub }` → nil = global in bypass; deliberately left). **Invariant making the substitution safe:** `!ok` can ONLY occur in bypass mode — RequireAuth 401s unauthenticated requests before any handler runs in auth mode — and all these handlers are mounted inside the protected `r.Group`, so the local-admin fallback can never grant an unauthenticated request access. **Regression guard:** `server/internal/api/bypass_auth_smoke_test.go` (`TestBypassAuth_NoProtectedRouteReturnsAuthError`) builds the full production router in `BypassAuth=true` against in-memory SQLite, `chi.Walk`s EVERY registered route, fires an unauthenticated request (loopback Host + matching Origin), and asserts none return 401/403 except an explicit `bypassSkip` allow-list (OAuth dance, bearer-auth ingress `/api/hooks/event|pre-tool` + `/api/mcp` + `/api/channel-reply`, SSE streams, `DELETE /api/me`). New routes are covered automatically. NOTE: the test sets a huge `AuthRateLimiterConfig` — without it the per-IP limiter (burst 20) 429s the 100+ rapid requests and masks the 401/403. When adding a new bearer-token route OUTSIDE the JWT group, add it to `bypassSkip`. `conf:high` (2026-05-30)
- **[backend/hooks]** `/api/hooks/*` has **two consumer classes with different auth**: hook-script ingress (`event`, `pre-tool`) carries `DASHBOARD_HOOKS_SECRET` (bearer) and mounts OUTSIDE the JWT group; the edit-gate UI (`pending` GET, `respond` POST) is called by the **browser** (`EditGateModal.vue`) with the session cookie, so it must mount INSIDE the protected JWT group and must NOT call `requireSecret` — otherwise the browser gets 401. Don't lump all hooks routes under one auth scheme. `conf:high` (2026-05-30)
- **[backend/rewrite-contracts]** The Go server rewrite silently changed several HTTP/SSE contracts the Vue frontend still expected in the old TS shape — and only the changed side was tested, so the divergence shipped green. Found in refine (2026-05-30): (1) `GET /api/refine/{id}/turns` now returns a **bare array**, but the frontend expected `{turns, isProcessing}` → `data.turns` undefined → "Failed to load history" on every fresh ticket; (2) `claude -p` emits **plain text** forwarded as `data: <line>`, but `sendMessage` did `JSON.parse` per frame and dropped non-JSON → assistant reply rendered blank. When auditing rewritten endpoints, **diff both sides of the wire** (Go handler response shape + JSON tags vs the TS `as SomeType` cast and SSE frame parsing), not just one. Tests that assert only the producer's shape (the Go `var x []any` unmarshal) give false confidence. Guarded by `src/composables/__tests__/useRefinementChat.test.ts`. STILL OPEN: refine phase tracking — backend never emits `event: phase_change` frames and `submitTurn` stores turns without `Phase`, so the phase stepper UI never advances during/after a refinement. `conf:med` (2026-05-30). THIRD manifestation (2026-06-01): the same `sendMessage` SSE parser **dropped all line breaks** — backend emits one `data:` frame per source line (bufio.Scanner strips the `\n`), but the client appended frame contents with no separator AND read only the first `data:` line per frame → markdown collapsed into one unformatted blob (headings/tables/lists dead). The **persisted** turn was fine (`runner.go` rebuilds with `sb+"\n"`), so it rendered correctly after reload — classic "broken live, fine after refresh" tell. Fixed: iterate every `data:` line, re-insert `\n` between lines (empty line → paragraph break), strip only one SSE space (keep markdown indentation). Guarded by `useRefinementChat.test.ts` line-break cases. `conf:high`. FOURTH + the big one (2026-06-01): the **refinement→pipeline concept handoff was never implemented** in the Go rewrite. `confirm()` (`api/refine/handler.go`) wrote nothing to `task.Metadata`/`Title`/`SourceBranch`, but `implementationBuilder` (`pipeline/stage_handlers.go:225`) reads the concept EXCLUSIVELY from `task.Metadata` → empty `{}` → implementation agent refuses ("No implementable task provided. Concept block was empty ({})"), title stays placeholder "New Task", user's branch/worktree wish ignored. The concept lived only in `refinement_turns`, never bridged. Also the refine prompt (`refine/spawner.go`) never asked the agent for a structured concept. Fix: (a) prompt now requires a fenced ```json concept block at approval (`refinedTitle`/`spec`/`plan`/`toolRequests`/`sourceBranch`/`targetBranch`) — note the Go backtick raw-string template can't contain a ``` fence, so the schema is a double-quoted `conceptSchemaInstruction` const concatenated in; (b) new `refine.ExtractConcept(turns)` (`refine/concept.go`) parses the LAST json block from the newest non-`confirmed` assistant turn; (c) `confirm()` persists it in ONE `UpdateTaskInput` — routing keys (refinedTitle→Title, sourceBranch→SourceBranch which auto-triggers `progress_guards.go` worktree creation, targetBranch→TargetBranch) lifted onto columns, the rest into Metadata. Frontend hides the json block from the bubble (`JSON_BLOCK_STRIP_RE` in `RefinementChat.vue` `cleanContent`) while still parsing it for the title. Guarded by `refine/concept_test.go` + `TestConfirm_PersistsConceptOntoTask`. `conf:high`
- **[git/danger]** NEVER run `git stash` followed by `git stash pop` to "temporarily" shelve changes when the working tree might be clean. `git stash` on a clean tree saves NOTHING ("No local changes to save"), so the subsequent `git stash pop` applies an unrelated OLD stash from the stack (this repo has 38+ leftover stashes) onto your tree — instant merge conflicts in random files. Happened 2026-05-30: a speculative stash/pop around a `git show` applied `refactor/unify-audit-events: follow-up agent leftovers` and conflicted di.go/handler.go/client.go. Recovery: committed work is safe in HEAD; `git checkout HEAD -- <conflicted files>` restores them (scoped, passes the destructive-action gate that blocks `git reset --hard`); the popped stash stays in the list (a conflicted pop does not drop it), so nothing is lost. To inspect a file at another commit use `git show <ref>:<path>` directly — no stash needed. `conf:high` (2026-05-30)

- **[backend/agent-monitor]** Monitor showed **identical session content for every Claude process in the same folder**. Root cause: `parser.FindSessionForProject` resolved sessions by **directory only** — `sessionCacheKey{cwd, configDir}` + `EncodePath(cwd)` projectDir, and `findSessionByContent` returned the newest-mtime JSONL for *all* same-folder PIDs (its `LastActivity < uptime+10s` filter is a per-process *plausibility* check, never an *identity* check). No PID→session binding existed anywhere; `merger.GetAgents` parallel-resolved each proc independently with no cross-proc distinctness. **Key non-discoverable fact:** Claude Code writes an authoritative PID→session map at `~/.claude/sessions/{pid}.json` = `{"pid","sessionId","cwd","status","entrypoint","version",...}` — but coverage is partial (only some live PIDs have one; older/resumed sessions may lack it). claude does NOT hold the `.jsonl` open (appends-and-closes) so lsof-fd mapping is useless. Fix (2026-06-01, branch `feat/layout-redesign`): layered per-PID resolver `parser.ResolveSessionForProcess(SessionRequest, claimed map)` in new `parser/pid_session.go` — precedence (1) `sessions/{pid}.json` → sessionId, (2) `--resume`/`--session-id` arg (`SessionIDFromArgs`), (3) dir mtime heuristic excluding the `claimed` set. `sessionCacheKey` gained a `pid` field; `findSessionForProjectFiltered(cwd,pid,uptime,cfg,claimed,forcedID)` is the new cache-backed core (`FindSessionForProject` is a `pid=0,forcedID="",claimed=nil` wrapper). Scanner switched `ps -eo pid,etime,comm` → `...args` so `--resume <id>` survives (`DetectProviderFromCommand` still strips to argv[0]). `merger.GetAgents` now **groups procs by (encoded cwd, configDir), resolves each group sequentially sharing one `claimed` map** (distinctness guarantee) while running groups in parallel (throughput); youngest proc resolved first so it claims the freshest session in fallback. Guarded by `parser/pid_session_test.go` (DistinctPerPID + FallbackDistinct regression tests). Trade-off accepted: a just-started agent whose `sessions/{pid}.json` names a not-yet-written `.jsonl` is skipped (shows nothing) until first write — correct, vs. previously showing a wrong session. `conf:high`
- **[frontend/refine]** Two RefinementChat reconnect bugs fixed (branch `feat/layout-redesign`): (1) **create-flow clobber** — `RefinementChat.vue`'s `watch([open, currentTask.id], loadHistory)` fired on the `null→newId` transition during task creation; `GET /turns` returns `[]` for a fresh task → `messages=[]` wiped the just-sent user message → the empty-state ("What would you like to build?") project-picker modal stayed stuck instead of switching to the chat view. Fix: `justCreatedId` guard in the component skips loadHistory for a locally-created id (sendMessage is the source of truth). (2) **no detached-run feedback on reopen** — the backend `refine.Runner` runs **detached** (survives client disconnect), persists the assistant turn **only at completion** (`runner.go`), and rejects a 2nd POST with `ErrAlreadyRunning` (no replayable live stream); progress is observable ONLY via `GET /api/refine/{id}/status`. The frontend never polled it → reopening mid-run showed just the user turn, frozen. Fix: `useRefinementChat` gained `runStatus`/`syncStatus`/`stop` — on (re)open the component polls `/status`, shows the working dots while `running`, reloads turns when it flips `done`. Also removed the composable's `watch(taskId)` reset (it raced the create flow's synchronous `isStreaming`/`runStatus` set) — `loadHistory` now resets phase state self-contained; `sendMessage` aborts via `AbortController` on close. **General rule:** when the backend exposes a detached-run + `/status` reconnect surface, the client must consume it — a one-shot history GET on open is not enough. Guarded by `RefinementChat.createflow.test.ts` + `useRefinementChat.test.ts` syncStatus/stop cases. `conf:high` (2026-06-01)
- **[frontend/d3-viz]** Two bugs broke the entire Workflows tab (visualizations) once the timestamp-400 was lifted (2026-06-02, branch `feat/layout-redesign`): (1) **blank charts** — all 4 viz components (`SankeyChart`/`SessionDagChart`/`SpawnTreeChart`/`CoOccurrenceMatrix`) used `watch(() => props.data, render, { immediate: true })` with the `<svg>` behind a `v-else`/`v-else` branch that only mounts once data is non-empty. The default (pre-flush) watcher fires BEFORE the DOM patch, so on first data arrival `svgRef.value` is still null → `render()` early-returns → permanently blank. Fix: `flush: 'post'` on all 4 watchers so render runs after the svg mounts. **Rule:** any imperative-render watcher that touches a template ref or `clientWidth` needs `flush:'post'` (or `nextTick`), especially when the ref is behind `v-if/v-else`. (2) **`Uncaught Error: circular link`** from `d3-sankey` — it only lays out DAGs, but `BuildSankey` (`analytics/visualizations.go`) emitted every `prev→curr` tool transition including self-loops (Read→Read) and bidirectional pairs (Read⇄Edit) → cycles → throw. Fix (backend, user chose DAG over `d3-sankey-circular`): skip self-loops while counting; new `acyclicSankeyLinks(map[[2]string]int)` collapses each bidirectional pair to a single **net-flow** edge (larger−smaller, equal→drop) then greedily removes back-edges (`firstBackEdgeIndex`, DFS gray-node detection, deterministic via pre-sorted links) until acyclic; nodes derived from surviving links. Frontend defense-in-depth: `SankeyChart.render` wraps the layout in try/catch → `renderError` ref shown as a message; the `<svg>` stays mounted (sibling of the error div, NOT gated behind it) so recovery re-render doesn't re-hit the null-ref mount race. Guarded by `analytics/visualizations_test.go` (net-flow/equal-drop/3-cycle-break/linear) + `handler_test.go` datetime-local cases. `conf:high` (2026-06-02)
- **[backend/session-parser]** `buildSessionInfo` (`server/internal/parser/sessions.go`) coupled cwd-capture to model-presence: `if m, cwd := extractHeadInfoRaw(headRaw); m != "" { projectPath = cwd }` — so when the first `model` sat past the 8KB head window (sessions opening with large attachments/prompts), the cwd (present on EVERY jsonl line) was discarded and ProjectName fell back to the raw encoded dir (`-Users-…`), plus CostEstimate stayed 0 (no model). Symptom surfaced app-wide: `/api/sessions` (and the new Workflows spawn-tree) showed encoded paths instead of real project names. Fix (2026-06-02, branch `feat/layout-redesign`): decouple — set `projectPath` from cwd whenever cwd != "" regardless of model; and recover model from the TAIL read (model is stable within a session) when the head missed it. Now ProjectName = `filepath.Base(realCwd)` (e.g. `agent-dashboard`) and cost/model populate when tokens exist (token counts come from the `session-meta/{id}.json` sidecar, which is often absent on older sessions → cost legitimately 0 there). Guarded by `sessions_test.go::TestBuildSessionInfo_CapturesCwdWithoutModel` + `_RecoversModelFromTail`. Lesson: when extracting multiple independent fields from one scan, never gate field B's assignment on field A being found. `conf:high`
- **[backend/cost-analytics]** Cost Analytics view (`/api/cost/summary` → `agent_cost_trends`) was permanently empty. Root cause was NOT wiring — the history importer (`server/internal/history/importer.go`) carries its **own** minimal JSONL parser (`parseTokensFromRaw`, distinct from the canonical `parser` package = SSOT violation) that filtered `type=="message"`, but Claude Code writes the token-bearing assistant turns with top-level **`type:"assistant"`** (nested `message.usage`). So it extracted 0 tokens from every modern session → `extractCostRow` returned nil → 0 rows. The unit tests used synthetic `type:"message"` fixtures encoding the same wrong assumption, so they passed green while production stayed empty — only a real-DB query (`sqlite3 ~/.claude/dashboard-tasks.db "SELECT count(*) FROM agent_cost_trends"`) exposed it. Fixed (2026-06-02, branch `feat/cost-auto-import`): match on `message.role=="assistant"` and accept `type` ∈ {`assistant`,`message`} (excludes tool_result/attachment). **Rules:** (1) when a feature reads on-disk formats, verify the parser against a REAL file, not just fixtures; (2) the two JSONL parsers (parser pkg + history importer) are a latent SSOT risk — prefer consolidating. The table is now filled by a server-side scan at boot + every `DASHBOARD_COST_SCAN_INTERVAL_MS` (default 300000); agents never write it. Multi-account/provider coverage comes from `parser.AllAgentConfigDirs()` (honours `DASHBOARD_CLAUDE_CONFIG_DIRS`) — default scans only `~/.claude`. `conf:high` (2026-06-02)
- **[backend/ent-codegen]** ent's `OnConflict`/upsert builders are **opt-in** via `--feature sql/upsert` in the `//go:generate` directive (`server/internal/db/ent/generate.go`); without it `.OnConflictColumns()` doesn't exist on the generated `*Create`. Also: this ent version only emits single-row upsert (`*XCreate.OnConflict…` → `XUpsertOne`), **NOT** bulk (`*XCreateBulk` has no `OnConflict`) — upsert N rows by looping single Creates inside one `client.Tx`. `XUpsertOne.UpdateNewValues()` refreshes all mutable cols except the immutable `id` (so it preserves the existing row id), but a field must be **mutable** (drop `.Immutable()`) to be refreshed on conflict. Regen gotcha: run ent codegen with `GOWORK=off go generate ./internal/db/ent/...`; the running `task dev`/`air` server + go test result-cache can mask codegen state — confirm with `grep -c OnConflict <file>` before trusting a build. And NEVER read `$?` after a pipe (`go build ... | head`) — the exit code is the tail command's, not the build's; chain with `&&` instead. `conf:high` (2026-06-02)
